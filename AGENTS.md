# AGENTS.md — rules for every agent and contributor

These rules bind every AI agent and every human contributor working in this repository.
They come before any task, instruction or deadline. `CLAUDE.md` holds the day-to-day
working notes; if the two ever disagree, **this file wins.** The verification agent
(`cargo xtask ci` and the review bot) checks contributions against this file.

## 1. Assets: only what we can prove we may use

An asset is any non-code material: icons, images, screenshots, logos, fonts, colour
profiles, sounds, video, and sample or test documents that are committed or published.

- **Nothing from Adobe products.** No icons, images, fonts, stamps, cursors, sample
  documents or UI graphics from Acrobat, Reader or any other Adobe product, installer or
  website. Never recreate, trace or imitate an Adobe icon. Our visual design is our own.
- **Only open, provable licences:** MIT, Apache-2.0, BSD-2/3-Clause, ISC, OFL-1.1, CC0-1.0,
  CC-BY-4.0, CC-BY-SA-4.0, public domain, or contributor-original work licensed under
  `MIT OR Apache-2.0`. If you cannot prove the licence from the original source, do not
  add it.
- **Every asset is attributed** in `ATTRIBUTION.toml` (path, author, source with version,
  SPDX licence, how it is used). `cargo xtask assets` fails on any asset without an entry.
- **Installed fonts are read, never shipped.** To draw a font a PDF does not embed, Folio may
  read a metric-compatible font already installed on the user's computer at run time. It is
  never copied, embedded, committed or packaged, and tests never depend on it (they skip
  when no such font exists).
- **Test documents are generated by code** (`folio_core::crashgen`, test helpers), never
  downloaded from the web.

## 2. Clean room

- Behaviour comes only from public specifications (ISO 32000-2, ISO 19005, ISO 14289,
  RFC 3161/5652, ETSI PAdES), public documentation and black-box observation.
- Never read, disassemble or copy anything inside an Acrobat installation.
- Never copy GPL/AGPL code (MuPDF, Ghostscript, Poppler, ...). Such tools may only run as
  separate oracle processes in tests, never linked and never read for implementation.
- Folio is not affiliated with Adobe. "Acrobat" names only the feature reference.

## 3. Never crash

Folio opens files from strangers. A malformed PDF, a bad argument, a corrupt settings
file or a full disk must produce an error the user (or agent) can act on — never a crash,
never a hang, never lost work. **This outranks feature work.**

- **Fail with `Result`.** Non-test code returns errors through the crate's error type.
  Lenient readers repair and record the repair (`Document::repairs`).
- **No panicking shortcuts** outside tests: no `unwrap`, `expect`, `panic!`,
  `unreachable!`, `todo!`, `unimplemented!`. The workspace denies them in clippy.
- **No `unsafe`.** The workspace sets `unsafe_code = "forbid"`.
- **Treat every number from a file as hostile.** Use `get()` rather than `[i]`, checked
  or saturating arithmetic, capped allocations, bounded recursion and loops
  (seen-sets, depth limits).
- **Write atomically.** Temporary file next to the target, then rename.
- **The anti-crash gate closes every stage.** `cargo xtask crash` mutates generated
  documents tens of thousands of times and runs every operation of the stage on each
  mutant. A stage is not done until it passes; see `PLAN.md` §4. Each new feature adds
  its operation to the crate's `tests/crash.rs`.
- **Prove fixes.** Every crash fix comes with a small regression test that failed before.

## 4. Headless first

- Every user-facing feature is reachable without a GUI: an engine API, then a `folio`
  command with `--json` output and an end-to-end test.
- Commands never overwrite an existing file unless `--force` is given.
- Any future network listener (MCP, UI control) is opt-in, loopback-only and
  token-authenticated. No telemetry, ever.

## 5. Honest parity

Every feature has an entry in `parity/acrobat-features.toml`. `partial`/`shipped` need
passing tests in `evidence` and `notes` saying what is still missing. `cargo xtask parity`
rejects claims backed by tests that do not exist.

## 6. Contributions

- Every commit is signed off (`git commit -s`, Developer Certificate of Origin).
- Run `cargo xtask ci` before opening a PR; CI runs the same gates.
- Fill in the PR template honestly; unchecked boxes block the merge.
